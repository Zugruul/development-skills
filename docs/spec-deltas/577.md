## §6.8 Brief preflight — MODIFIED (supersedes the "one stderr line" wording of delta 573)

WHEN `scripts/brief-preflight.sh <agent-name>` refuses a dev, reviewer or pr-reviewer brief, THE
SYSTEM SHALL check every rule in one pass (the `## TODO UPKEEP` section is present; the section
names a task id) and SHALL print ONE refusal on stderr that lists every failed rule, numbered, then
the complete `## TODO UPKEEP (required)` block to paste. The block SHALL be filled in where it can:
the role from the agent name (`dev-*` is `dev`; `reviewer-*` and `pr-reviewer-*` are `reviewer`),
the task id from the brief (`Task id X` anywhere, else `issue #N`), else from a numeric agent name
(`dev-571`, `reviewer-571-spec`), else left as `N` with a line saying to replace it. The exit code
stays 1; the hook's deny reason carries the whole refusal. The block SHALL be the same text
`implement-task/SKILL.md` shows (pinned by a test), and the skill SHALL say, where the brief is
described, that the section is mandatory and is copied verbatim including its first line
`Task id N; your role is <role>.`.

## §7.11 Board truth audit (#564) — MODIFIED

- The In progress rule SHALL move a card through normal WIP admission. The audit SHALL NEVER pass
  `--over-wip` and SHALL NEVER move a card over the WIP limit; a refusal for a full limit SHALL be
  printed as `NOTE #N: not moved <from> -> <to> (<why>): WIP limit full (X/Y); ...`, SHALL leave the
  card where it is and SHALL NOT count as a failed fix.
- A live worktree or open PR with no linked issue SHALL be printed as `NOTE: DISCREPANCY: <worktree
  or PR> has no issue; if it is real work, run board.sh ensure-issue --title "<title>" --for-branch
  <branch>`. The audit SHALL NEVER create an issue; filing one is the orchestrator's deliberate
  `ensure-issue` call.
- Lanes whose branch starts with `worktree-agent-` or `batch/`, or whose worktree directory starts
  with `worktree-agent-`, SHALL never be adopted, linked or reported as unlinked; they SHALL only be
  counted in one `NOTE: ignored N agent/batch lane(s) ...` line.
- A link SHALL be, in order: the `audit-links.json` record; a single board card whose title carries
  the task id found in the branch name (the first `<letters>[/-]<digits>` unit, so `sc/226-x` is
  `SC-226`, compared case-insensitively by prefix and numeric value); the branch's own `<id>` when
  that issue is on the board; a `Closes/Fixes/Resolves #N` in the PR body. Two cards carrying the
  same task id SHALL be ambiguous and never guessed.
- The audit SHALL print progress lines (`audit: ...`) on stderr, and the fix pass SHALL stop making
  moves once `BOARD_AUDIT_BUDGET_SECONDS` (default 90, counted from the start of the `board.sh audit`
  command) is spent, printing one `NOTE: audit time budget (Ns) reached; ...` line; it SHALL NOT
  count as a failure.
- API budget: mutations only through `board.sh move`; the `ensure-issue` read and write paths no
  longer run from the audit.

## §7.2 board.sh remove — ADDED

THE SYSTEM SHALL provide `board.sh remove <issue#>`, which deletes the issue's board item with
`gh project item-delete` (item id from the local cache, else one board read; a stale cached id is
dropped and resolved once more from the board), drops the cache entry and prints `removed #N from
the board (the issue itself is unchanged)`. A number not on the board SHALL exit 1 with an error;
a missing or non-numeric argument SHALL be a usage error (exit 2); a failed delete SHALL exit 1 with
`ERROR: could not remove #N ...`. The issue itself SHALL NOT be closed or edited.

## §7.2 Review passes for orchestrator PRs — ADDED (docs)

The skills implement-task and build-next SHALL state, next to the issue-first rule, that every
orchestrator PR, however small, needs the two tagged review passes (spec-compliance, code-quality)
recorded before merge, not only before QA. implement-task §0.4 SHALL give a registration-commit title
with no scope (`chore: register work for <task-id> (#N)`), since an empty commit changes no scope and
scope-checking commit-msg hooks refuse a scope that names no changed area, and SHALL say to follow the
hook's message if it still refuses.
