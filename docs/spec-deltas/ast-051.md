## §13.2 — DECIDED (STT engine choice, human-answered, issue #333)

**Section changed**: §13.2 (Voice — STT).

**Before** (SPEC-ASSISTANT.md, current text):

> §13.2 STT: E5 decides Web Speech (zero-install; audio leaves the machine) vs
> whisper.cpp sidecar (local); the engine API stays text-in/text-out either way. The
> choice SHALL be recorded as a spec delta before implementation.

**After** (final, paste-ready replacement text):

> §13.2 STT: THE SYSTEM SHALL support BOTH engines, selectable per-session in the
> neural-view voice ⚙ settings panel: `whisper` (whisper.cpp, fully local —
> the DEFAULT) and `web-speech` (the browser's Web Speech API, zero-install; audio
> leaves the machine to the browser vendor). The setting SHALL persist across page loads the
> same way the panel's other voice settings do. WHEN whisper.cpp is selected THE
> SYSTEM SHALL talk to a local whisper sidecar over a documented HTTP contract (a
> capability-provisioned process, out of THIS decision's scope — see the whisper
> capability, E6); WHEN the sidecar is unreachable THE SYSTEM SHALL surface an honest
> "whisper sidecar not available" state naming both the follow-up capability and the
> Web Speech alternative, never a generic/silent failure. Either engine's recognized
> text SHALL enter the SAME downstream text path as typed chat input — the engine API
> stays text-in/text-out regardless of the STT choice.

**Why**: The human was asked a structured decision on issue #333 (E5's STT choice,
gating AST-051/AST-052 per §13.2's own "SHALL be recorded as a spec delta before
implementation" rule) and answered: ship both engines, selectable in Settings, with
whisper.cpp — fully local, privacy-preserving — as the default, and Web Speech kept
available as the zero-install door for anyone without (or not wanting) the local
sidecar. This is privacy-by-default without removing an easy on-ramp: a user who
hasn't installed the whisper capability yet is never blocked from using voice input,
they just get an honest nudge toward either installing it or flipping the setting.
Recording this here, before AST-051's implementation code, is the spec invariant
§13.2 itself names — the STT decision is a contract change (which engines exist, what
the default is, what "unavailable" means) and must exist as a reviewable delta before
any of that contract is implemented against.

## Implementation notes (this task, AST-051 — not a further spec amendment)

- The setting lives in the template's existing `uiState` (localStorage-backed,
  `nv-ui` key) as `uiState.sttEngine: "whisper" | "web-speech"`, defaulting to
  `"whisper"` when unset — same persistence path as `uiState.vdir`/`uiState.micMode`
  and the rest of the voice ⚙ panel's settings (AST-022's area).
- The whisper.cpp CLIENT (not the sidecar itself) assumes this local HTTP contract,
  documented here for whoever builds the sidecar capability (E6, AST-060/061):
  `POST http://localhost:<sidecar-port>/transcribe`, `multipart/form-data` with one
  field `audio` (a `Blob`, `audio/webm` from `MediaRecorder`) → `200
  {"text": "<transcript>"}` on success. Any network failure or non-2xx response is
  read as "the sidecar isn't running/installed", never as a transcription error —
  the client surfaces the honest unavailable message instead of a generic one.
- Deferred (reported to the orchestrator to file as follow-up scope, NOT built by this
  task): the whisper.cpp sidecar's install, model download, and process
  lifecycle/management — a capability-shaped concern (capability.yaml +
  provisioning check) that lands with E6's provisioning machinery per AST-060/061.
- §13.3 spans: `stt-start`/`stt-end` trace events (engine name in the payload) ride
  the same trace-event path TTS spans use, via a new thin bridge route,
  `POST /assistant/voice-event`, added to `engine.py` alongside `_chat`/`_select`
  (enqueue-only over the existing `_emit_trace`/`observability.emit` — no new writer,
  §10.2's single-writer rule holds).
- §17.9 hard gate: STT cannot start while `window.assistantGate.gated` is true (no
  assistant selected) — checked client-side before either engine's `start()` runs,
  and server-side too (`/assistant/voice-event` refuses to record a span for a gated
  session, mirroring `/assistant/chat`'s own gate check).
