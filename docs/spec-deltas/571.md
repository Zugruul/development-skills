## §6.8 Task state — MODIFIED

WHEN `board.sh move N <status>` moves a task to the board's working status (`statusFlow[1]`)
and no record exists, THE SYSTEM SHALL create it: the issue title, the status, agent
`orchestrator`, and one TODO per unchecked `- [ ]` acceptance criterion in the issue body, in
body order, skipping fenced code blocks and, WHEN the body has an "Acceptance criteria" heading, taking
only that section's (checked `- [x]` items SHALL NOT be added). WHEN the body has no unchecked criterion,
THE SYSTEM SHALL add one TODO, "Meet the issue's acceptance criteria". An existing record SHALL
keep its TODOs and change only its status.

THE SYSTEM SHALL make no extra GitHub call in the normal path: `board.sh show N` SHALL save the
issue title and body to `.claude/board-issue-N.json` (atomic write; gitignored runtime state,
excluded in `tree-state.sh` and `local-state.manifest`), and `move` SHALL use that copy. Only
WHEN the copy is missing SHALL `move` make exactly one REST `GET /repos/{repo}/issues/N`, and
never GraphQL, and none WHEN the move was queued or made by `board.sh audit --fix`. WHEN that read fails or the body is malformed, THE SYSTEM SHALL create no record
and print one stderr line saying so.

WHEN a task moves to the review status (`statusFlow[2]`) or QA (`statusFlow[3]`), THE SYSTEM
SHALL update the record's status; WHEN no record exists, it SHALL print one warning line to
stderr naming the task and the `task-state.sh set` command that creates one. The move SHALL
never fail because of task-state.

THE SYSTEM SHALL keep the record at QA, so retro, feedback and closure TODOs stay visible, and
SHALL clear it only WHEN the task moves to a status in `statusFlow[4:]` (Ready, Deployed or
later), or by `task-state.sh clear`. Statuses SHALL be compared ignoring case and runs of
spaces, and with several boards the roles SHALL be the union across boards.

The tasks panel SHALL show only task-state records; it does not read a repo's `TODO.md`. The
`task-state` skill and the plugin README SHALL say so and describe the auto-created record.

## §7.4 board.sh show — MODIFIED

WHEN `board.sh show N` succeeds, THE SYSTEM SHALL also save the issue's title and body as
described in §6.8, adding no API call; a failed save SHALL NOT fail `show`.
