## §7.3 Recorded gate pass — MODIFIED (one pass per worktree)

- `gate.sh` SHALL record the pass in a marker per tree: the primary checkout keeps
  `<primary>/.claude/gate-pass`; any other worktree uses
  `<primary>/.claude/gate-pass.d/<first 16 hex of sha256(canonical worktree toplevel)>`.
  The content stays the tree-state fingerprint (HEAD + uncommitted diff) of the tested tree.
  A red gate SHALL clear only that tree's marker.
- `gate-preflight.sh` SHALL look up the marker for the tree it checks (same rule), so one
  lane's gate never invalidates another lane's pass.
- The tree fingerprint SHALL exclude `.claude/gate-pass.d/` like `.claude/gate-pass`, so a
  worktree gate writing into the primary checkout never invalidates the primary's pass.
- `.claude/gate-pass.d/` is local state (`ignore` in the local-state manifest).
- The PreToolUse move guard SHALL judge the tree named by the hook payload's `cwd` when it
  is an absolute, existing directory inside a git checkout; otherwise the hook process cwd,
  as before. A literal leading `cd <path> &&` before the board.sh segment still wins (#151).

## §9.2 Red-first preflight — MODIFIED (base and override)

- The branch's commits SHALL be those reachable from the branch and from NEITHER
  `refs/heads/<mainBranch>` NOR `refs/remotes/origin/<mainBranch>`. When an `origin` remote
  exists the check SHALL first fetch `origin/<mainBranch>` (best effort, 30 s bound,
  `RED_FIRST_NO_FETCH=1` skips it); a failed fetch prints a NOTE and uses the refs on hand.
- WHEN the check fails and `RED_FIRST_OVERRIDE` holds a reason of at least 20 characters,
  THE SYSTEM SHALL record `{"kind":"red-first-override","task":<branch>,"commit":<sha>,
  "reason":...}` in telemetry and pass with a WARNING; a shorter reason, or a reason that
  cannot be recorded, SHALL still block. The block message SHALL name the override. This
  covers red proved by reverting the fix (test and fix committed together).
