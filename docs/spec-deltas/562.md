## §9.2 user-accepted work evidence — ADDED

WHEN the human accepts work the reviewer did not APPROVE, THE SYSTEM SHALL accept
`board.sh move <n> QA --accepted-by-user "<quote>"` (also `--accepted-by-user=<quote>`).
BEFORE the two-pass review guard runs, so the same move passes, it SHALL first record a
telemetry event `{"kind":"user-acceptance","task":"<n>","quote":"<quote>","ts":"<iso8601>"}`
and then post one issue comment holding the quote and the words "Accepted by the user without
a reviewer APPROVE". The comment SHALL be one REST call
(`gh api -X POST repos/<repo>/issues/<n>/comments`); no `gh issue comment` (GraphQL) call and
no new read SHALL be made. IF the task's latest acceptance is still valid by that rule, THEN the
event and the comment SHALL both be skipped (a retry only needs the move); otherwise a fresh
event and comment are made. IF the comment fails (rate limit
or other), THEN THE SYSTEM SHALL warn on stderr and continue the move; the event holds the quote.

THE SYSTEM SHALL treat a `user-acceptance` event for a task as satisfying both
`two-pass-review-preflight.sh` and `review-round.sh approval-check` for that task, in place of a
completed latest APPROVE, only if it was recorded after the last review round of that task in
`telemetry.jsonl` (append order; timestamps are never compared) and no round is pending; a later
review round or a pending reservation overrides it. It SHALL NOT
satisfy any other task.

IF the quote is empty or whitespace-only, or the move target is not QA, THEN THE SYSTEM SHALL
refuse with a non-zero exit, record nothing and make no gh call. A flag before the status, a flag
without a value, or any other `--` option as the fourth argument SHALL be a usage error (exit 2)
naming the flag. Without the flag and without an APPROVE, the QA move SHALL remain refused.
