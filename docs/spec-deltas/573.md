## §6.8 Brief preflight — ADDED

WHEN an orchestrator briefs a dev or reviewer agent, THE SYSTEM SHALL provide
`scripts/brief-preflight.sh <agent-name>`, which reads the brief on stdin and exits 1 with one
stderr line naming the problem WHEN the agent name matches `^(dev|reviewer|pr-reviewer)-` (case-insensitive)
and the brief has no `## TODO UPKEEP` heading, or that section does not name a task id (`Task id
<id>`, with an optional `:` or `#` before the id, as in `Task ID #573`, where `<id>` is an issue number or a letters/digits/`-`/`_` id). Any other agent name, and
any brief that has the section with a task id, SHALL pass with exit 0.

THE SYSTEM SHALL ship a `PreToolUse` hook (acting only for tool_name `Agent` or `Task`) on the matcher `Agent|Task` in the plugin's
`hooks/hooks.json` (`scripts/guard-brief-preflight.sh`) that runs the check for the subagent-spawn
tool and blocks the spawn with a `permissionDecision: "deny"` decision carrying the script's line.
The agent name SHALL be `tool_input.name` when present, else the first whitespace-separated word of
`tool_input.description`; the brief is `tool_input.prompt`. The hook SHALL be active only when the
repo has spec-workflow config (`.neural-network/project.yaml`), SHALL allow (with one stderr note)
on any internal error such as malformed JSON or a missing python3, and SHALL make no network call.

The skills `implement-task` and `build-next` SHALL document the check next to the TODO UPKEEP rule,
including the description convention (start the description with the agent name, for example
"dev-571 task-state move").

## §9 Build-loop & enforcement parity (E3) — Codex parity note

WHERE Claude's `PreToolUse` hook is unavailable (Codex), THE SYSTEM SHALL keep the same rule as an
explicit workflow step: Codex users run `scripts/brief-preflight.sh <agent-name>` by hand on the
brief before delegating to a dev or reviewer agent. Decisions stay in the script; the hook is only
the Claude Code trigger.
