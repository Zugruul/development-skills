## §6.4 — CHANGED (persona interview + `set-persona` verb, issue #486)

**Section changed**: §6.4 (`/setup-assistant` scaffold contract).

**Before** (SPEC-ASSISTANT.md, current text):

> §6.4 WHEN `/setup-assistant` runs THE SYSTEM SHALL scaffold: marker, project.yaml with
> assistant section, empty brain directories, persona-scoped AGENTS.md, and gitignore
> entries for all assistant local state.

**After** (final, paste-ready replacement text):

> §6.4 WHEN `/setup-assistant` runs THE SYSTEM SHALL scaffold: marker, project.yaml with
> assistant section, empty brain directories, persona-scoped AGENTS.md, and gitignore
> entries for all assistant local state. WHEN the scaffold is fresh (or
> `assistant.systemPrompt` still equals the bare default) THE SYSTEM SHALL interview the
> human — via the host's structured-input facility — about this project's assistant
> (domain, tone, boundaries, example tasks) and compose a quality persona from the
> answers, applied through a `set-persona` verb that writes the composed text into BOTH
> `assistant.systemPrompt` (via the same snapshot → surgical edit → §6.5 validation →
> revert-on-invalid pattern every other settings verb uses) and a new marker-delimited
> persona block in the root `AGENTS.md`, regenerated in place — hand-written prose
> outside the markers SHALL survive byte-for-byte, and re-running `set-persona` SHALL be
> idempotent and is the supported way to evolve the persona later. Empty/whitespace-only
> persona text, and persona text containing a line matching one of `AGENTS.md`'s own
> reserved generated-block markers, SHALL be rejected (`project.yaml` and `AGENTS.md`
> both left byte-identical); text exceeding the runtime engine's persona-component clip
> (3200 chars by default — `turns.py`'s persona token budget of 800, converted at 4
> chars/token, and itself overridable) SHALL still be accepted and stored in full — never
> silently truncated — with a warning naming the actual clip.

**Why**: Issue #486 (P0, human-directed). Before this change, `/setup-assistant`
scaffolded a single generic, one-line `assistant.systemPrompt`
(`You are <name>, the local assistant for this repository's zettel brain...`) and a bare
persona `AGENTS.md`, with no mechanism for tailoring either to what the assistant is
actually FOR in a given repo. Every scaffolded assistant read the same identity
regardless of the project — a bug-triage bot and a writing companion got byte-identical
personas. The interview step closes that gap: the orchestrating skill now asks the human
four concrete questions (domain, tone, boundaries, example tasks) immediately after a
fresh scaffold and composes a real persona from the answers, instead of leaving the bare
scaffold as the permanent default.

## Implementation notes (this task, #486 — not a further spec amendment)

- `scripts/assistant/setup.py` gained `set_persona(root, text)`: writes
  `assistant.systemPrompt` through `apply_setting` (the same
  snapshot/surgical-edit/`validate_assistant`/revert-on-invalid machinery
  `set_provider`/`set_model` already use — no new validation path was needed,
  since `validate_assistant`'s existing `systemPrompt` non-empty check already
  rejects empty/whitespace-only text and reverts the file byte-identical).
- A third marker-delimited block was added to `AGENTS.md`'s generated-block family
  (`PERSONA_START`/`PERSONA_END`, alongside the pre-existing `GEN_START`/`GEN_END`
  "enabled skills" block and `OUT_START`/`OUT_END` "file output contract" block),
  regenerated in place via the existing `_replace_or_append_block` helper — so it
  inherits the same "prose outside the markers survives byte-for-byte, re-runs are
  idempotent" guarantee the other two blocks already had. Unlike those two, the persona
  block is only ever written by `set_persona`; scaffold's `ensure_agents_md` never
  touches it and never overwrites a `systemPrompt` that `set_persona` already set (the
  per-leaf skip-if-present scaffold behavior needed no change — it already leaves any
  present key alone).
- `_default_agents_md` gained an optional `persona_block` parameter: when `set_persona`
  runs against a repo whose `AGENTS.md` doesn't exist yet, the persona block is placed
  right after the H1. The normal case — an existing `AGENTS.md` from a prior `scaffold`,
  which always carries the bare one-line default intro (`You are <name>, the local
  assistant for this repository's zettel brain.`) — replaces that exact line in place on
  first application, rather than leaving the generic intro sitting above the real
  persona (or appending the real persona below everything, including the generated
  skills/output-contract blocks). If that exact line isn't found (a human already
  hand-edited the intro away), the block is inserted right after the H1 instead — never
  appended at EOF. A re-run (persona markers already present) goes through
  `_replace_or_append_block` as normal.
- Runtime clip: `turns.py` gained a public `persona_char_budget(budgets=None)` accessor
  — `DEFAULT_COMPONENT_BUDGETS["persona"]` (800) is a TOKEN budget, not chars;
  `persona_char_budget()` returns the actual compose-time CHAR clip
  (`_cap_chars(_resolve_budgets(budgets), "persona")`, 3200 by default), the exact
  conversion `compose_context` itself applies. `setup.py` derives its
  `_PERSONA_RUNTIME_CLIP` from this accessor instead of hand-duplicating (and, in this
  task's first pass, getting wrong — reviewed and fixed) the token→char math. Text over
  the clip is accepted and stored in full in both `project.yaml` and `AGENTS.md`; a
  warning is printed (to stderr, prefixed `WARNING:`) naming the actual derived clip so
  the composing agent (or human) knows the excess only lives in the stored persona, not
  in what a live turn actually sends the model.
- Marker-injection guard: persona text containing a line that exactly matches one of
  `AGENTS.md`'s six reserved marker lines (`GEN_START`/`GEN_END`, `OUT_START`/`OUT_END`,
  `PERSONA_START`/`PERSONA_END`) is rejected before either file is touched — an embedded
  `PERSONA_END` would duplicate without bound on re-runs, an embedded `GEN_START`/
  `OUT_START` would make the next scaffold's block scanner silently discard everything
  after it.
- Clean-failure handling: a missing/unreadable `--file` path is now a `REJECTED:`
  message and a nonzero exit from the CLI, not an uncaught `FileNotFoundError`
  traceback. If `assistant.systemPrompt` writes successfully but the subsequent
  `AGENTS.md` write fails (e.g. unwritable), `set_persona` reports that explicitly —
  `project.yaml` and `AGENTS.md` are now out of sync — with a nonzero exit, rather than
  silently leaving a half-applied persona or reverting the already-successful
  `project.yaml` write.
- `setup-assistant.sh` (bash wrapper) gained `set-persona --file <path|->`; `--file -`
  reads the persona text from stdin, so the composing agent never has to shell-quote a
  multi-line prompt inline — it writes the composed text to a temp file (or pipes it)
  instead.
- `plugins/spec-workflow/skills/setup-assistant/SKILL.md` documents the interview as
  "scaffold step 2": what to ask (domain, tone, boundaries, example tasks), composition
  guidance (identity stated once, keep `systemPrompt` tight since the runtime clips it,
  fuller prose lives in `AGENTS.md`), and that re-running `set-persona` is the supported
  way to evolve the persona later.
