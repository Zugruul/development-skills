## ADDED — §7.1 Runtime inventory coverage

WHEN a shipped plugin introduces a repository-owned runtime output, the workflow SHALL classify its default path in the canonical local-state manifest as local/derived `ignore` state or durable shared `track` state. Directory entries SHALL cover their descendants, with explicit derived exceptions permitted inside tracked directories. Source audits SHALL include every plugin's skills, scripts, references, generated templates and capability payloads, and SHALL record source sites and coverage or an evidence-based exclusion for external state, caller-selected paths, browser storage, generated project source and test fixtures. Caller-selected overrides SHALL remain the consumer's responsibility. The workflow SHALL NOT introduce blanket ignore patterns to conceal unknown output paths.

## ADDED — §7.2 Preflight freshness and validation

WHEN preflight resolves an existing project configuration, in either normal or `--spec` mode, it SHALL invoke the existing configuration validator against that resolved configuration path and SHALL compare the repository's managed ignore block through `gitignore-sync.sh --dry-run`. IF the configuration is invalid, the block is missing or stale, or freshness cannot be established because inspection fails, preflight SHALL emit an actionable `PREFLIGHT FAIL` naming the affected target and validator evidence or a safely quoted repair command, and SHALL NOT report a clean core preflight result. Preflight SHALL preserve its exit-zero skill-loader contract; skill callers SHALL stop on `PREFLIGHT FAIL`. A current block and valid configuration SHALL add no successful-check transcript. Preflight SHALL NOT repair files automatically and SHALL preserve independent checkpoint, identity, assistant, cache and design advisories.

## ADDED — §7.2 Temporary ownership and diagnostics

WHEN gitignore synchronization completes successfully, fails, or receives handled INT, TERM or HUP, it SHALL remove its own temporary artifacts, including when TMPDIR points inside the consumer repository. It SHALL NOT remove arbitrary user files and SHALL make inspection, rendering, comparison, publication and cleanup failures visible. SIGKILL and power-loss cleanup are outside this guarantee. Dry-run SHALL preserve the target bytes; apply SHALL preserve bytes outside the managed block and SHALL retain warnings for tracked paths ignored by non-managed rules. Malformed managed markers SHALL be reported as inspection errors.

## MODIFIED — §7.3–§7.4 Shared authority

The manifest SHALL remain the sole path-policy registry and gitignore-sync SHALL remain the sole managed-block rendering/comparison authority for both preflight and the mem013 sync-project-configs rule. WHEN an explicit repair applies the current manifest, a subsequent preflight SHALL accept that managed block without drift diagnostics. Configuration validity SHALL remain owned by the existing validator, including supported legacy formats and local overlay semantics; preflight SHALL NOT duplicate schema validation or perform automatic migrations.
